# 质量门禁执行手册

以开发标准第 15.3、16.1、16.5 节为准。命令定义统一放在 `scripts/check_quality.py` 中。产品 CLI 保持原有入口。

使用 `uv lock --check` 和 `uv sync --frozen --all-groups` 准备环境。
日常检查使用 `uv run --frozen python scripts/check_quality.py --mode local`，
完整检查使用同一入口的 `--mode full --base-sha <40位比较基准SHA>`。
可以通过 `--check lint` 等选项执行单项检查。
`local` 模式省略覆盖率和安全扫描，因此判断 PR 是否达到完成条件时，需要通过 `full` 模式或全部 CI 检查。

总体行覆盖率至少为 85%，差异行覆盖率至少为 90%。按开发标准固定比较基准。
差异中的可执行行数为 0 时，确认 diff-cover 显示分母为 0，并记为 N/A。
安全扫描使用网络审核依赖项和获取钩子。常规测试和冒烟测试使用模拟 LLM。

结果保存到 `.review/quality/<检查名或模式>.json`。
任何失败或未执行的检查都会使总体结果判为失败。完成报告须包含执行命令、退出状态和未执行项。
公开日志或报告前，确认其中没有敏感值。

GitHub 上的 PR 执行 Quality 工作流。手动执行时，必填参数 `base_sha` 须指定由 40 位小写十六进制字符组成的比较基准提交 SHA。
PR 使用固定的 base SHA，手动执行使用指定 SHA 与 HEAD 的合并基点。
未知提交及格式错误的输入一律拒绝。差异覆盖率生成 JSON，并记录分母为 0 的情况。
在分支保护中，将 `dependency-sync` 和 `checks` 矩阵的全部任务设为必需检查。
由仓库管理员确认设置。实际合并限制取决于分支保护配置。

Python 统一使用 3.14 系列。`pyproject.toml` 中的 `==3.14.*` 拒绝其他次版本，
本地和 CI 共用 `.python-version` 指定的 3.14。补丁版本可以在 3.14 系列内升级。
