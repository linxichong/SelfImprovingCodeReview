# 评估数据的用途与独立性管理

以概要设计第 15.2～15.7 节、M2 详细设计第 12 节、开发标准第 15.4 节为准。
本文定义用途、已知性和证据管理规则。现有的 `split=dev/test`、JSON Schema、数据库、CLI、总体样本和成功阈值保持不变。
用途分类需要人工管理。

## 三种用途

| 用途 | 允许开展的工作 | 可支持的评估结论 |
|---|---|---|
| 开发调优集 | 调整提示词和规则，按审批流程生成记忆候选 | 开发比较 |
| 已知缺陷回归集 | 复现已知误报、漏报和边界缺陷并检查回归 | 已知用例的回归结果 |
| 冻结的独立验收集 | 独立验证和审批与调优隔离的固定候选，随后开展验收评估 | 具备独立性记录且满足正式条件时，可以作出正式判定 |

候选、已完成技术检查、已验证、已审批、已发布是不同的状态。审批和发布状态由各自流程更新。
固定应答 Dataset 测试仅提供模拟运行的证据。

## 现有资料的处理

- `datasets/development/python_rule_candidates/` 用于开发调优。
- test-v9 和 test-v10 是基于已知结果订正的候选，归入已知缺陷回归集。
  保留其未审批状态和旧版本引用。判定是否未见以实际阅览与使用记录为准。
- 判断独立验收候选的独立性时，须检查对输入、正确答案和模型输出的阅览记录，检查调优使用记录，以及验证者和审批者的记录。
- `datasets/test/` 下的固定 LLM 应答用于自动化测试，与正式正确答案集分别管理。

## 固定项和阅览记录

比较前固定数据集 ID、版本、哈希、目标 Commit、用例和问题 ID、无问题用例、创建和验证及审批的状态与负责人，
以及模型、提示词、规则、记忆和执行计划。
记录同一 PR、文件、模块、高度相似的用例和修订源之间的关系，检查数据集之间有无泄漏。
分开记录为创建候选或进行技术检查而发生的阅览，以及向评估对象调优负责人披露的内容。
仅将能够确认未见性的资料用作独立验收证据。

阅览结果后调整提示词、规则、记忆或正确答案时，须说明它们之间的关系。
原用例及其高度相似的订正版仍归入已知用例。
订正保存为新版本，并保留原数据集和原判定。即使按同一版重跑所有组别和轮次，结果也是在订正版上重新评估。
要作出新的独立性结论，须使用与调优隔离的其他资料，并完成现有的独立验证和审批流程。

## 比较报告

变更提示词或规则时，使用[比较记录](templates/评估变更_比较记录.md)，按相同的固定条件比较变更前后。
按组别、用例和轮次保留记录，同时报告 TP、FP、FN，漏报和误报，严重问题 ID 的保留和缺失，以及 Token、延迟和费用。
逐轮报告，以暴露特定轮次的回归。有条件差异时应明确标注，因果判断须基于同等条件。
无法取得的费用记为不可取得。分母为 0 时按正式设计记为不可评估。

所有评审都成功后才对比较指标评分并确认。发生失败则返回 `INCOMPLETE_REVIEW_RUNS`。
只有满足规定的总体样本、各至少 3 轮、未裁定项为 0 等现有条件，才作正式 B/C 判定。
严重问题须确认 B 所有轮次的检出 ID 并集被 C 的每一轮涵盖。
开发集和回归集上的比较结论只适用于相应用途。

## 技术检查与人工验收

技术记录须包含固定引用的一致性、复现结果、哈希、CLI 检查和执行状态。
将 AI 检查明确记为建议。独立人工确认由实际人员完成。
人工验证、裁定和审批须另行记录实际负责人、操作、理由、时间与安全的审计引用。
未执行的事项标为未执行。CLI 的 `is_evaluation_ready` 只验证技术条件。
独立阅览记录和人工验收须另外提供证据。

报告不得保存敏感输入、完整提示词或未经处理的应答。
只有在现有外部发送权限已显式启用且已配置密钥时，才运行真实 LLM。整理文档时禁止自动调用真实 LLM。
